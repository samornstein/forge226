# Portable athlete state, schema version 1

Maintain `athlete-state.json` outside the skill directory. Save immutable copies under `versions/` before changing an active state. Use a temporary file and atomic replacement where possible. Keep generated outputs in `exports/`, raw data in `imports/` and receipts under `receipts/`. Never overwrite source uploads. Do not distribute a populated athlete state as part of this skill.

Canonical top-level fields:
- `schemaVersion`: 1; `athleteId`: local opaque string; `version`: positive integer; `parentVersion`: integer or null; `status`: draft or active; `generatedAt`: ISO timestamp; `timezone`: IANA timezone.
- `athlete`: object containing `name`, experience by sport, background, equipment, current weekly hours, preferences, and `thresholds` with sport/value/units/test date/method/source/confidence. Unknown fields are null, not invented defaults.
- `goal`: object with `name`, `startDate`, `endDate` (inclusive YYYY-MM-DD), `raceDate` (same as endDate for pre-race plans, otherwise null), distance, priority and goal rationale.
- `availability`: seven keys `Monday` through `Sunday`, each with `AM` and `PM` objects `{ "enabled": true|false|null, "minutes": number|null }`. Disabled slots count as zero. Unknown enabled slots block an executable schedule until resolved.
- `weeklyCapMinutes`: number or null for no lower cap. Capacity is derived from enabled slots. Cap is not a volume target.
- `exceptions`: array of `{ "startDate", "endDate", "reason", "slots": { "AM": {"enabled":false,"minutes":0}, "PM": {...} } }`. Inclusive dates; supplied slots replace recurring slots. Omitted slots inherit. Do not permit overlapping exception ranges without consolidating them first. Store equipment/access restrictions as additional fields and review them separately.
- `strategy`: phase objects, principles, limitations and approval/version metadata.
- `sessions`: array of `{ "id", "date", "slot", "sport", "title", "minutes", "intensity", "details", "purpose" }`. Date is local ISO date; slot is AM, PM, Rest or Race. Sport is Swim, Bike, Run, Strength, Other, Rest or Race. Minutes are nonnegative. Rest has slot/sport Rest and zero minutes. Race uses slot/sport Race only on goal.raceDate. Add `provisional`, `thresholdRef`, `alternative` and `successCue` as needed. At least one entry per date, including explicit rest/travel days. Keep brick legs separate with a shared optional groupId; do not add an aggregate duration row.
- `activities`: normalized actual records with stable ID, source, timestamp/date, sport, duration, units, provenance and optional matched session ID. Do not infer completion from planned data.
- `checkins`: dated readiness reports. `analysis`: findings with methods, coverage and confidence. `evidence`: source receipt entries. `changes`: dated revisions/reasons. `review`: review type, findings and check results.

Keep additional fields when revising state. Reject unknown newer schema versions instead of silently discarding data. Import legacy `athlete-profile.json` / `training-plan.json` or supplied Forge226 exports with an explicit mapping. Stage the converted state as a draft and flag missing values; never read another athlete's local application database just because a copy of the skill is installed. A supplied workout CSV may lack strategy, thresholds or AM/PM constraints: request only those missing essentials. Existing desktop data is not connected automatically.

The HTML output is a snapshot of this state. It is not the source of truth and does not update a workbook. Import edited Excel actuals deliberately using stable session IDs, preserve evidence and resolve conflicts; do not overwrite the plan from arbitrary changed cells without review.

## Coaching record version 1 (additive; portable schema stays 1)

Newly generated plans include `coachingVersion: 1`. Older saved states without it remain readable; upgrade on the next coaching revision. The validator checks the following fields when the marker is present:

- `assessment`: `{evidenceDate, track, disciplineExperience, baseline, goalDemands, feasibility, rationale, priorities, uncertainties, nextAction}`. Dates use YYYY-MM-DD; track is completion/performance/qualification; feasibility is supported/stretch/insufficient-evidence/reconsider. disciplineExperience maps each relevant sport to a description; priorities is 1–3 strings, uncertainties an array. Text fields explain actual evidence rather than boilerplate. Optional `timeScenarios` preserves sourced/assumed splits and summed totals. No qualification probability.
- For qualification, `assessment.qualification`: `{status: "verified"|"unverified", timeGoalRelation, unknowns}`. Verified also requires event, championshipYear, ageGroup, competitionCategory, rulesUrl, checkedAt and rulesSummary. Unknowns explicitly include uncertainty about the future field/slot acceptance. Unverified means training can proceed but qualification rules/outcomes are not established.
- `trainingBlocks`: array of `{id, startDate, endDate, focus, rationale, progressIf, repeatIf, reduceIf, checkpoints}`. Blocks are within the horizon, do not overlap, and cover every training session via its `blockId`. A checkpoint is `{date, measure, criterion, status: "planned"|"met"|"not-met"|"unknown", evidence?}`. Met/not-met require evidence. Later blocks and sessions are provisional.
- Each non-rest/non-race session has `blockId`. Detailed (not provisional) sessions require `alternative` and `successCue` as well as existing prescription fields.
- `reviewDecisions`: array of `{date, action, evidence, reason, changes, nextReviewDate}`. action is continue/progress/repeat/reduce/reschedule/pause/reassess. Initially may be empty; revisions require a decision. Keep previous decisions and append the latest. `review` remains the separate pre-activation validation/review record.
- `sessionOutcomes`: optional array of `{sessionId, confirmed:true, status, basis, activityIds?:[], actualMinutes?}`. Status: completed/shortened/extended/substituted/missed-confirmed/unknown. `basis` records who/what confirms it. One activity may be linked to only one session; preserve separate brick legs. For an unsplit device recording, keep matches unknown or deliberately create a documented split before linking. Self-reported sessions can supply minutes without activity IDs. A missed-confirmed session has zero actual minutes and no activity IDs. Do not create confirmed outcomes merely from unique heuristic candidates.

Profile fields used by analysis (save with get_profile/save_profile; copy relevant athlete context into the plan):
- `evidenceCoverage`: `[{startDate,endDate,complete:true,basis}]` explicitly confirms that all relevant training/rest is represented across the inclusive interval. Source-sync success or a first/last workout does NOT establish complete coverage. Only save when the athlete or reconciled records support this assertion. Update it when sources are disabled, imports change, or a gap is discovered.
- `benchmarks`: `[{id,sport,metric,value,units,date,method,source,conditions}]`. Store historical entries; never overwrite an older result or merge different methods/conditions. Numeric values use consistent units (e.g. seconds/km, not formatted pace text). Unknown facts remain unknown and are flagged unverified by analysis. `thresholds` remains the separate current prescription reference; a new benchmark does not silently change zones.

Exports preserve saved `analysis` coaching findings and add `calculatedAnalysis`, `benchmarkHistory` and `adherence` with their own evidence dates. Latest imported evidence is not a fresh coaching assessment. These additions never replace immutable prior plan versions.

## Guided intake and qualitative profile (additive)

Keep the athlete's reported `experienceLevel` (beginner/intermediate/advanced) and `similarEventHistory` separately from experience/capability by sport. A beginner triathlete with a marathon result is not a beginner in every discipline. Keep dates and the post-event routine separate from earlier training volume.

Save qualitative answers in `profile.coachingContext` and copy relevant context to `state.athlete.coachingContext`: motivation, concerns, recovery/energy, sleep, work/family/stress demands, training preferences, support, strength experience and fueling experience. Preserve the athlete's words and distinguish interpretation from reported fact. Optional unknown/skipped answers stay null or explicitly unknown; do not infer numerical scores or diagnoses. Assessment and block rationales should explain how these answers change training decisions.

Use `profile.intake` for resumable conversation progress: `{flowVersion:1,currentStage:1..6,stageStatus:{direction,baseline,qualitative,availability,constraints,optionalData},answeredFields:[],acceptedUnknowns:[],deferredFields:[],essentialGaps:[],nextQuestion:null|string}`. Stage statuses are pending/in-progress/complete/skipped. Record actual facts in their normal profile fields; answeredFields references those fields rather than creating competing copies of answers. Accepted unknowns and an optional-data decline can complete a stage. For files-only fallback, retain the same structure in the saved athlete profile outside the distributable folder; do not claim persistence until written.

On resume, inspect the profile and prior conversation, reconcile progress against actual answers and ask only the next useful question. The checklist helps prevent repetition; it is not a gate requiring every optional answer. Do not rewrite previously saved profiles or active plans merely because the skill was updated; merge these fields during actual intake/revision. Connection data is the final default step; no source account is required to complete intake.

## Machine-checked date-specific limits (0.8 additive)
Exceptions may include `maxMinutesPerDay` (nonnegative total across AM/PM, including a race if scheduled) and `allowedSports` (array of canonical sport names). Use these for daily holiday caps and equipment/travel access instead of relying only on prose. Omitted fields preserve legacy behavior. Rest is always allowed; active-recovery walks use Other and must be included when allowed. Overlapping exceptions must still be consolidated. Human coaching review checks actual equipment, pool access, intensity and recovery suitability.
