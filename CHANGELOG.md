# 0.8.0

## Coaching and reusable workflows
Review full history and typical weekday patterns before prescribing the season. Separate re-entry load, historically repeated volume and availability. Persist rest/active-recovery preferences. Use conditional repeated build weeks, realistic peaks, travel and recovery adjustments. Never treat one athlete’s schedule as a template for all athletes.

## Tools and presentation
Added forge226_history_summary and forge226_garmin_sync_all. Added generic month/week/day calendar, phase navigation, workout detail and consistent totals to the bundled dashboard. Existing schemaVersion 1 plans remain readable.

## Reliability
Use same-origin form referrer policy while retaining strict Host, Origin and CSRF validation. Use verified macOS system CA fallback only when Python has no default trust bundle; explicit certificate configuration remains authoritative. Explain TLS/network/form/key failures separately. Record lock owner metadata without automatically terminating processes. Disable canonical PTY line buffering while the same-chat runtime is active, restoring it on exit.

## Privacy and limits
No athlete profile, plan, history, wellness, tokens, personal hosting IDs or credentials are included. Providers still require each athlete’s authorization. No automatic cloud sync, new Garmin metrics, or public publishing is added. Tests use synthetic data; live provider availability and real-account behavior can vary.
